# 📋 기획서 (PRD) : 나에게 맞는 사주 해석 서비스

> 이 문서는 누구에게 어떤 경험을 제공할지 정한 개발 기준입니다.

작성일: 2026-09-23

작성자: 참가자와 Codex

---

## 1. 풀고자 하는 문제

- **지금은 이렇게 해요:** 기존 사주 서비스를 찾아 결과를 읽거나, 현재 시작 코드에서 생년월일·출생시간을 입력해 사주 계산값을 확인합니다. 참가자의 실제 이용 방식은 아직 확인하지 않았습니다.
- **이게 불편해요:** 처음 보는 사람에게는 용어가 어렵고 해석이 뻔하게 느껴질 수 있습니다. 사주를 즐겨 보는 사람도 자신에게 맞는 해석과 관심 주제에 대한 깊이 있는 설명을 원합니다.
- **이렇게 되면 좋겠어요:** 기본 맞춤 해석을 쉬운 말로 읽은 뒤 관심 주제 하나를 골라 자신에게 더 관련 있는 설명을 확인합니다.

## 2. 사용자

- **누가 쓰나요?** 사주를 처음 접하는 사람과 이미 사주를 즐겨 보는 사람.
- **언제 쓰나요?** 자신의 사주를 살펴보고 특정 관심사에 대해 더 알고 싶을 때.
- **어디서 쓰나요?** 브라우저에서 여는 웹 서비스. 휴대전화 화면 지원 범위는 구현 전에 확인합니다.

## 3. 입력 자료

- **입력 내용:** 양력 생년월일과 출생시간, 대운 방향 계산에 사용할 성별. 기본 해석을 본 뒤 관심 주제 네 가지 중 하나를 선택합니다. 성별은 성격 판단이 아니라 전통 규칙에 따른 대운 순행·역행 계산에만 사용합니다.
- **관심 주제:** 성격·강점, 연애·관계, 일·진로, 재물.
- **현재 필수 항목:** 시작 코드에서 양력 생년월일과 출생시간은 필수입니다. 출생시간을 모르는 사용자를 어떻게 처리할지는 미정입니다.
- **개인정보 포함 여부:** 생년월일과 출생시간은 개인과 연결될 수 있는 정보입니다. 서비스 이용 전 구글 로그인을 요구하며, 계정별 저장을 추가할 때는 본인 결과만 볼 수 있어야 합니다.
- **로그인·저장 기반:** 구글 로그인은 Supabase Auth, 계정별 결과는 Supabase Postgres를 사용합니다. 마이그레이션과 앱 코드를 작성하고 2026-09-28 `sta-saju` 운영 프로젝트에 적용했으며, 실제 사용자 계정 사이의 접근 격리 검증은 아직 남아 있습니다. 해석 생성 기준은 `docs/specs/002-gemini-reading.md`를 따르며, 실제 문장 품질은 계속 확인합니다.

## 4. 핵심 기능과 구현 순서

1. 생년월일과 출생시간을 입력하면 현재 계산 기능을 바탕으로 기본 맞춤 해석을 쉬운 말로 보여줍니다.
2. 기본 해석을 본 뒤 네 가지 관심 주제 중 하나를 선택하면 그 주제에 맞는 자세한 해석을 보여줍니다.
3. 구글 계정 로그인 후에만 사주 입력·계산·해석을 이용할 수 있게 합니다.
4. 로그인한 사용자가 결과를 저장하고 나중에 다시 열어보는 기능은 로그인과 함께 확인합니다.

**구현 순서:** 기본 해석 → 관심 주제별 상세 해석 → 구글 로그인 필수화 → 계정별 결과 저장·재열람. 앞의 두 경험은 먼저 구현했으며 정식 서비스에서는 로그인 확인 전 이용할 수 없게 합니다.

- **AI에게 맡길 것:** `gemini-3.5-flash-lite`가 계산된 사주 구성을 바탕으로 쉬운 기본 해석과 선택한 주제의 상세 해석 문장을 만듭니다. 사주 계산은 현재 `lib/saju`가 담당합니다.
- **사람이 확인할 것:** 해석이 쉬운 말인지, 주제와 관련이 있는지, 단정적이거나 오해를 부를 표현이 없는지 확인합니다.

## 5. 결과와 완료 조건

- **결과물과 저장 위치:** 기본 해석과 선택한 주제의 상세 해석을 웹 화면에 표시합니다. 로그인 도입 전에는 성공한 결과를 사용 중인 브라우저의 `localStorage`에 저장해 다시 열 수 있게 합니다. 마지막 단계에서는 구글 로그인과 계정별 저장으로 확장할지 검토합니다.
- **정상 입력:** 유효한 생년월일·출생시간을 입력하면 기본 해석이 보이고, 예를 들어 `일·진로`를 고르면 해당 주제의 상세 해석이 보입니다.
- **마지막 단계의 저장 확인:** 구글 로그인 후 결과를 저장하면 다시 방문했을 때 본인의 결과를 열 수 있습니다. 다른 사람의 결과는 볼 수 없어야 합니다.
- **입력 또는 처리 실패:** 날짜·시간이 빠지거나 유효하지 않으면 수정할 항목을 알려줍니다. 해석 생성이나 저장이 실패하면 실패 사실과 재시도 방법을 보여주며 결과를 만들어진 것처럼 표시하지 않습니다.

## 8. 이번 작업 범위와 시간

- **2026-09-23 프로토타입 범위:** 기존의 생년월일·출생시간 입력과 사주 계산 결과를 보여주고, 그 다음 화면에서 관심 주제 네 가지 중 하나를 선택하는 흐름을 구현합니다. 주제 선택 후에는 선택 상태와 이후 제공할 영역의 자리만 보여줍니다. 사주 해석 문구, AI 생성, 로그인, 결과 저장은 이 프로토타입에 넣지 않습니다.
- **프로토타입 이후 목표:** 기본 맞춤 해석 → 관심 주제 하나 선택 → 상세 해석을 검토합니다.
- **2026-09-23 해석 기능:** `docs/specs/002-gemini-reading.md`를 기준으로 Gemini 기본·주제별 해석과 `localStorage` 저장·재열람을 구현했습니다. 로그인은 여전히 이번 범위에서 제외합니다.
- **로그인 정책 변경 (2026-09-23):** 정식 서비스에서도 로그인 전에는 사주 입력·계산·해석·브라우저 저장 결과에 접근할 수 없게 합니다. 계정별 저장·재열람은 별도 구현 단계입니다. 로그인 시험 모드에서는 비용을 막기 위해 Gemini 해석을 계속 비활성화합니다.
- **계정 저장 구현 (2026-09-23, 운영 DB 적용 2026-09-28):** 현재 결과 한 건을 사용자가 직접 Supabase Postgres에 저장하고 다시 여는 코드를 작성했습니다. 과거 `localStorage` 결과는 자동 이관하지 않습니다. `sta-saju` 운영 데이터베이스에 마이그레이션을 적용했으며, 서로 다른 실제 계정의 접근 제한 검증 전까지 완료로 간주하지 않습니다.
- **일간 분석 1차 기준 (2026-09-23):** 월지의 대표 오행, 지장간의 같은 오행(뿌리), 일간을 제외한 일곱 글자의 도움·소모·제어 관계를 코드로 살핍니다. 세 단서가 한 방향일 때만 보수적인 결론을 내고, 엇갈리면 판단을 보류합니다. 합·충, 대운·세운과 성별에 따른 대운 방향은 후속 단계입니다. 자세한 기준은 `docs/specs/008-conservative-day-master-assessment.md`를 따릅니다.
- **구성 화면 개선 (2026-09-23):** 먼저 년·월·일·시의 윗글자/아랫글자 8칸을 한자·한글·오행 색으로 보여줍니다. 바로 아래에 오행 다섯 개의 가로막대와 일간을 기준으로 한 짧은 해석을 두고, 자세한 계산 근거는 펼쳐 보게 합니다. `판단 보류`가 전체 해석의 결론처럼 보이지 않게 합니다. `docs/specs/009-eight-character-visual-reading.md`를 따릅니다.
- **심화 해석 1차 범위 (2026-09-23):** 일간과 나머지 일곱 글자의 십성, 천간의 어울리는 짝, 지지의 어울리는 짝과 부딪히는 짝을 코드로 계산해 쉬운 말로 보여줍니다. 세 글자가 모이는 관계와 형·해·파 등 복잡한 관계는 앞으로 별도 Spec에서 개발합니다. 자세한 기준은 `docs/specs/010-ten-gods-and-pair-relations.md`를 따릅니다.
- **대운·세운 1차 기준 (2026-09-23):** 남성·여성 입력과 출생연도 천간의 음양을 전통 규칙에 적용해 순행·역행을 정합니다. 첫 대운은 `lunar-javascript`의 기본 환산법(`sect=1`)으로 계산하며, 현재 대운과 그 기간의 세운을 일간 기준 기본 오행 관계로 설명합니다. 십성 및 합·충 심화 해석은 별도 영역에서 다룹니다. `docs/specs/011-gender-fortune-cycles.md`를 따릅니다.
- **세 기능 통합 (2026-09-28):** 심화 해석, 대운·세운, 계정별 결과 저장이 한 화면에서 만나는 동작과 남은 실계정 검증은 `docs/specs/012-integrated-reading-and-account-storage.md`를 따릅니다.
- **오늘의 운세 기획 (2026-09-28):** 로그인 후 `오늘의 운세 보기`와 `사주 보기` 중 선택합니다. 오늘의 운세에 필요한 `내 사주`가 없으면 직접 입력하거나 계정에 저장한 해석 결과를 선택하는 팝업을 보여줍니다. 사용자의 결정에 따라 양력 생년월일·출생시간·성별을 **별도 계정 프로필 DB에 보관**하며, 기존 해석 결과 테이블에는 추가하지 않습니다. 과거 저장 결과에는 원본 입력이 없어 가져올 때 다시 입력·일치 확인을 합니다. 매일 한국 시간 오전 9시대 예약 작업이 대운·세운·일운의 계산 근거와 짧은 해석을 미리 생성·저장하되 **오늘의 운세 생성용 Gemini 요청만** 계정당 하루 최대 한 번입니다. 기존 기본·주제별 사주 해석 횟수는 제한하지 않습니다. 세부 기준과 운영 비용 관련 미결정 사항은 `docs/specs/013-daily-fortune.md`를 따릅니다.
- **실습 종료 시각과 남은 시간:** 안내받지 않아 미정입니다. 구현을 시작할 때 실제 시간을 확인해 순서를 조정합니다.

## 9. 첫 구현 목표 (30분 예산)

현재 계산 결과와 관심 주제 선택을 한 화면에서 직접 확인합니다. 해석과 로그인은 넣지 않습니다. 30분은 완료 약속이 아닌 첫 확인 목표의 작업 예산입니다.
