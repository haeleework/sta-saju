# 010-ten-gods-and-pair-relations: 십성과 글자 짝으로 읽는 심화 해석

상태: 구현 및 검증 완료 (2026-09-23)

작성일: 2026-09-23

## 목표

기존 8글자 도표, 오행 풀이, 보수적인 일간 분석에 이어 일간과 나머지 일곱 글자의 십성 관계와 글자 사이의 합·충을 계산합니다. 결과는 사주를 처음 보는 사람도 읽을 수 있는 짧고 쉬운 한국어로 보여줍니다.

십성은 “나를 나타내는 일간과 다른 글자가 어떤 역할로 만나는지 붙인 열 가지 이름”으로 소개합니다. 예를 들어 나와 같은 편인지, 내가 표현하는 쪽인지, 내가 관리하는 쪽인지처럼 일상적인 뜻을 먼저 말하고 전문 용어를 함께 표시합니다.

## 계산 범위

### 십성

- 기준은 일주의 천간인 일간입니다. 음양과 오행의 생·극 관계를 함께 사용해 비견·겁재·식신·상관·편재·정재·편관·정관·편인·정인을 구분합니다.
- 일간 자신은 십성 목록에서 `나를 나타내는 기준 글자`로 표시하고, 나머지 천간 3개와 지지 4개의 십성을 계산합니다.
- 지지는 대표 오행만으로 음양을 추측하지 않고, 각 지지의 중심이 되는 지장간인 본기를 기준으로 십성을 계산합니다. 본기 대응표는 현재 `lunar-javascript@1.7.7`의 지장간 자료와 맞춥니다.
- 지장간 전체의 십성, 비율·점수·순위는 계산하지 않습니다.

### 글자 사이의 합·충

- 천간 네 글자 사이에서 천간오합(甲己, 乙庚, 丙辛, 丁壬, 戊癸)을 찾습니다.
- 지지 네 글자 사이에서 지지육합(子丑, 寅亥, 卯戌, 辰酉, 巳申, 午未)과 지지육충(子午, 丑未, 寅申, 卯酉, 辰戌, 巳亥)을 찾습니다.
- 같은 종류의 짝이 여러 위치에 있으면 년·월·일·시의 위치를 구분해 모두 남깁니다.
- 합은 `두 글자가 서로 연결되는 단서`, 충은 `두 글자가 서로 다른 방향으로 움직이는 단서`라고 설명합니다. 실제 관계의 좋고 나쁨이나 사건 발생을 확정하지 않습니다.
- 합으로 다른 오행이 되었다고 판정하거나, 합·충 때문에 기존 일간 분석의 결론을 자동으로 바꾸지 않습니다. 성립 강도, 계절 조건, 방해 글자까지 판단하지 않기 때문입니다.

## 화면과 해석

- 오행 분포 풀이 아래에 `글자 관계를 한 걸음 더 보기` 영역을 둡니다.
- 십성은 일곱 글자를 위치, 글자, 쉬운 역할, 전문 이름으로 읽을 수 있게 보여줍니다. 같은 십성이 반복되면 모든 위치를 유지하되, 아래 설명에서는 반복되는 역할을 한 번 묶어 읽기 좋게 요약합니다.
- 합·충은 발견한 짝과 위치를 보여줍니다. 해당 관계가 없으면 오류처럼 보이지 않게 `이번 여덟 글자에서는 바로 맞닿는 짝을 찾지 못했습니다`라고 안내합니다.
- 계산으로 확인한 값과 전통 명리의 해석을 구분합니다. 성격·관계·직업·재물·미래를 단정하지 않고, 실제 경험을 돌아볼 질문이나 가능성으로 표현합니다.
- 자세한 계산 근거는 기존 펼침 영역에 유지합니다. 기존 8글자 도표와 오행 풀이가 먼저 보이도록 순서를 바꾸지 않습니다.

## Gemini와 저장

- Gemini에는 서버에서 다시 계산한 십성과 합·충 결과만 전달합니다. 모델이 관계를 다시 계산하거나, 제공하지 않은 관계를 만들어 내거나, 합·충을 사건 예언으로 바꾸지 못하도록 안내합니다.
- 기존 `해석 만들기`와 주제 선택 요청에서만 해당 자료를 사용합니다. 자동 또는 추가 Gemini 호출은 만들지 않습니다.
- 실제 Gemini 호출은 이번 검증에서 하지 않습니다. 프롬프트의 내용과 형식은 자동 검사에서 확인합니다.
- 기존 저장 형식은 바꾸지 않습니다. 저장된 차트에서 새 분석을 다시 계산하므로 과거 저장 결과도 열 수 있어야 합니다.

## 이번 범위에서 제외하고 앞으로 개발할 내용

- 지지 삼합·방합, 천간충, 형·해·파
- 지장간 전체의 십성 및 주기·중기·여기 가중치
- 합화의 성립 여부와 합·충의 세기 판정
- 용신, 대운·세운, 운세 시기 예측

이 항목들은 기준과 설명 방법을 별도 Spec에서 정한 뒤 개발합니다.

## 완료 조건과 검사

1. 모든 천간과 지지 본기에 대해 십성 열 가지가 음양·오행 규칙대로 계산됩니다.
2. 천간오합, 지지육합, 지지육충의 모든 표준 짝과 관계가 없는 사례를 자동 검사합니다.
3. 화면에서 용어의 쉬운 뜻, 일곱 글자의 역할, 발견한 합·충, 단정하지 않는 요약을 읽을 수 있습니다.
4. Gemini 프롬프트에는 계산된 십성과 합·충만 들어가며 원본 생년월일·출생시간·비밀키는 들어가지 않습니다. Gemini 실제 호출은 하지 않습니다.
5. 기존 계산·저장·로그인·해석 API 테스트, 형식 검사, 전체 자동 검사, 배포용 빌드와 `git diff --check`가 모두 통과해야 완료로 표시합니다.

## 검증 결과

- 구현 담당과 분리된 테스트 담당 서브에이전트가 관련 테스트를 작성·보강하고 실행했습니다.
- `npm run check`: 형식 검사와 전체 자동 검사 51개 통과. 새 검사에서는 십성 10종, 12지지의 본기, 천간오합 5쌍, 지지육합 6쌍, 지지육충 6쌍, 관계 없음과 중복 위치 사례를 확인했습니다.
- 화면 소스 검사에서 기존 8글자·오행 풀이 다음에 일곱 글자의 쉬운 역할과 합·충 설명이 나오고, 자세한 일간 계산 근거보다 먼저 표시되는 것을 확인했습니다. 작은 화면에서는 십성 카드가 한 열로 바뀝니다.
- Gemini 프롬프트에 서버가 계산한 십성과 합·충이 포함되고, 삼합·방합·천간충·형·해·파를 만들거나 합화·사건을 단정하지 말라는 제한과 원본 날짜·시간·비밀키 미포함을 자동 검사했습니다. 실제 Gemini 호출은 하지 않았습니다.
- `npm run build`: 성공. `git diff --check`: 오류 없음(Windows 줄끝 변환 안내만 표시).
- 예시 계산 결과를 직접 읽어 일간을 제외한 일곱 역할, 지지 본기, 발견한 짝과 단정하지 않는 요약 문장을 확인했습니다. 기존 저장 형식과 API 호출 횟수는 바꾸지 않았습니다.
