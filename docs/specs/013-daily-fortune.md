# 013-daily-fortune: 내 사주 기반 오늘의 운세

상태: 앱 코드·운영 DB 마이그레이션 작성 및 적용 · 실계정·배포·예약 실행 검증 전

작성일: 2026-09-28

선행 기능: `003-google-login.md`, `004-account-reading-storage.md`, `011-gender-fortune-cycles.md`

## 목표와 사용자 결정

- 로그인 직후 첫 화면에서 **`오늘의 운세 보기`**와 **`사주 보기`** 중 하나를 고릅니다. 사주 보기는 기존 입력·계산·해석 화면으로 이동합니다.
- 사용자는 계정별 `내 사주` 프로필 한 건에 **양력 생년월일·출생시간·성별**을 등록·수정·삭제할 수 있습니다. 직접 입력하거나 계정에 저장된 해석 결과 중 하나를 출발점으로 선택할 수 있습니다. 저장 결과 여러 건 중 최근 것을 자동으로 본인 정보로 간주하지 않습니다.
- 매일 한국 시간 기준 오늘의 운세를 미리 만들어 DB에 보관하고, 사용자가 `오늘의 운세 확인하기`를 누르면 **저장된 내용**을 보여줍니다. 버튼을 누를 때마다 Gemini를 새로 호출하지 않습니다.
- 한국 시간 오전 9시 이후 그날 처음 `내 사주`를 등록했다면 등록 성공 직후 오늘 운세 생성을 한 번 시작합니다. 오전 9시 전 등록자는 예약 실행 대상입니다. 두 경로 모두 같은 날짜의 중복 방지·비용 상한을 적용합니다.
- 사용자가 단순히 다른 사람의 사주를 시험하거나 해석 결과를 계정에 저장했다는 이유만으로 매일 AI 비용이 발생하지 않습니다. `내 사주` 프로필을 **명시적으로 등록한 계정만** 생성 대상입니다.
- 첫 버전은 대운(약 10년 흐름)·세운(올해 흐름)·일운(오늘 흐름)을 모두 반영합니다. 이 계산은 코드에서 하며 **오늘의 운세 생성용 Gemini 요청만** 계정당 한국 날짜 하루 최대 1회입니다. 계산 근거가 늘어 요청당 입력량은 소폭 늘 수 있습니다. 기존 기본 사주·관심 주제 해석 요청에는 이 횟수 제한을 적용하지 않습니다.

## 현재 코드와 선행 변경

- 현재 `public.saju_readings`는 사용자가 명시적으로 저장한 **해석 결과 여러 건**을 보관합니다. `내 사주` 표시나 매일 생성 여부는 없고, **원본 생년월일시·성별도 없습니다.** 이 기존 결과 테이블은 그대로 두고 새 `내 사주` 프로필 테이블에 출생 정보를 보관합니다.
- 기존 대운 계산은 생년월일시와 성별이 필요합니다. 과거에 저장한 8글자만으로 원본 입력을 안전하게 복원할 수 없습니다. 따라서 과거 결과를 `가져오기`로 선택한 경우에도 생년월일시·성별을 입력받고, 다시 계산한 8글자가 선택한 결과와 일치할 때만 등록합니다.
- 사용자 본인 결과만 보이는지 두 실제 계정으로 검증하는 기존 `004`의 완료 조건도 이 기능의 배포 전에 확인해야 합니다.

## 사용자 흐름과 화면

1. 구글 로그인 성공 후 선택 화면에 `오늘의 운세 보기`와 `사주 보기`를 동등하게 표시합니다. 상단 계정 표시·로그아웃은 유지하고, 두 화면 사이에 돌아갈 수 있는 탐색을 둡니다. 선택 화면에 들어왔다는 이유만으로 Gemini를 호출하지 않습니다.
2. `오늘의 운세 보기`를 눌렀는데 등록된 `내 사주`가 없으면 `내 사주 정보를 먼저 입력해주세요!`라는 팝업(대화 상자)을 띄웁니다. `직접 입력`, `저장된 사주 결과에서 가져오기`, `닫기` 중 하나를 선택하게 합니다. 저장 결과가 없다면 `가져오기`는 사용할 수 없는 이유를 안내합니다. 팝업은 키보드로도 열고 닫을 수 있어야 합니다.
3. `직접 입력`에서는 양력 생년월일·출생시간·성별을 입력하고 내용을 확인한 뒤 `내 사주`로 등록합니다. 화면 표기는 간단히 `성별`로 하고, 계산에서는 대운 방향에도 이 값을 씁니다. 서버가 값을 검증·계산하며, 등록 성공 전에는 운세가 준비된 것처럼 표시하지 않습니다.
4. `저장된 사주 결과에서 가져오기`에서는 본인 계정의 해석 결과 중 한 건을 고릅니다. 선택 전에는 출생 정보 입력칸을 숨기고 `직접 입력으로 바꾸기`를 항상 보여줍니다. 과거 결과에는 출생 원본이 없으므로 결과를 고른 뒤 생년월일시·성별을 추가 입력받고, 다시 계산한 사주 8글자가 선택 결과와 같을 때만 `내 사주`로 등록합니다. 빈 목록·읽을 수 없는 저장 행·조회 실패를 구분해 안내합니다. 다른 계정의 결과와 브라우저 `localStorage` 목록은 자동으로 가져오지 않습니다.
5. `내 사주`가 이미 있으면 오늘 한국 날짜의 **저장된 운세 상태**를 조회합니다. 성공 결과가 있으면 `오늘의 운세 확인하기` 버튼을 눌러 오늘의 한 줄, 그렇게 읽은 이유, 오늘 해볼 작은 행동을 보여줍니다. 계산 근거와 해석 문장을 구분하고 미래 사건을 확정하지 않습니다.
6. 한국 시간 오전 9시 이후 `내 사주`를 **처음 등록**하면 등록 성공 직후 서버에서 오늘 운세 생성을 한 번 시작하고, 화면에는 `오늘의 운세를 준비 중입니다`를 표시합니다. 완료되면 저장된 결과를 `오늘의 운세 확인하기`로 볼 수 있습니다. 오전 9시 전 등록자는 예약 실행을 기다립니다. 등록 정보가 있지만 결과가 없거나 생성에 실패했다면 해당 상태·이유를 안내합니다. 전날 결과를 오늘 운세처럼 보여주거나 결과 확인 버튼 클릭만으로 새 AI 요청을 만들지 않습니다.
7. `내 사주`를 수정하면 프로필 버전을 올려 이전 정보로 만들어진 오늘 결과를 새 사주의 결과처럼 보여주지 않습니다. **첫 등록 이후의 수정은 즉시 생성 조건이 아니며**, 이미 그날 Gemini 요청을 시도했다면 수정해도 다시 호출하지 않습니다. 계정 저장 결과를 삭제해도 별도 `내 사주` 프로필은 자동 삭제하지 않으며, 삭제 화면에서 이 차이를 안내합니다. 사용자는 `내 사주` 프로필 자체를 별도로 삭제할 수 있습니다.
8. 로그아웃하거나 계정을 바꾸면 이전 계정의 등록 정보·오늘 운세·메모리 캐시를 즉시 숨깁니다.

## 운세 계산과 AI의 역할

- `lib/saju`가 등록 사주와 오늘 날짜(한국 시간 기준)로 오늘의 간지와 오행·일간 관계를 계산합니다. 등록 시 계산한 대운 기준과 기존 `011`의 규칙으로 현재 대운·세운도 구하고, 세 흐름을 **계산 근거**로 구분해 둡니다. 대운·세운·일운이 같은 방향이라고 해서 특정 사건이 반드시 일어난다고 단정하지 않습니다.
- Gemini는 **계산된 사실을 바꾸지 않고** 읽기 쉬운 문장으로 풀어 씁니다. 기존 `gemini-3.5-flash-lite`와 서버 전용 `GEMINI_API_KEY`를 재사용합니다. 대운을 넣어도 추가 Gemini 호출은 만들지 않고, 한 번의 프롬프트에 필요한 계산 근거만 간결하게 넣습니다.
- 오늘의 운세 생성에 한해 계정당 한국 날짜 하루 **Gemini 요청 최대 1회**와 성공 결과 최대 1건을 지킵니다. 요청 직전에 시도 상태를 영속적으로 선점해, 응답이 유실되거나 Cron이 중복 호출되어도 같은 날 재요청하지 않습니다. 출력은 `summary`, `reason`, `action` 등 고정 형식으로 검증하고 빈 문장·형식 오류·계산과 모순되는 해석은 저장하지 않습니다. 불안감을 주는 예언이나 건강·금전상의 단정적인 지시는 하지 않습니다.
- 모든 계정을 합쳐 한국 날짜 하루 **오늘의 운세용 Gemini 요청 최대 30회**로 제한합니다. 예약 실행과 오전 9시 이후 첫 등록 직후 생성을 합산하며, 실패한 요청도 호출 횟수에 포함합니다. 두 경로가 동시에 실행돼도 서버의 영속적·원자적 상한 선점으로 31번째 요청을 시작하지 않습니다. 기존 기본 사주·관심 주제 해석 요청은 이 30회에 포함하지 않습니다.
- Gemini에 구글 이메일, 원본 생년월일시, 성별, 인증 토큰을 보내지 않습니다. 필요한 계산 결과와 오늘 날짜만 보냅니다.

## 예약 실행과 실패 처리

- Vercel Cron은 프로덕션의 `GET /api/cron/daily-fortune`를 호출합니다. 한국 오전 9시의 UTC 표현은 `vercel.json`의 `0 0 * * *`입니다. Vercel Hobby 플랜에서는 그 시각이 정확한 9시가 아니라 **9:00~9:59 KST**일 수 있으므로 화면은 `오전 9시부터 순차 준비`로 안내합니다.
- `CRON_SECRET`을 Vercel 서버 환경변수로 설정하고 `Authorization: Bearer ...`를 검사합니다. 값이 없거나 틀리면 실패 상태로 닫고, 비밀값을 응답·로그·브라우저에 노출하지 않습니다.
- Cron은 `auth.users` 전체가 아니라 `내 사주`를 지정한 활성 프로필을 **등록이 오래된 순서**로 페이지 단위 조회합니다. 초기 버전은 한 번에 최대 300개 프로필을 살펴보며, 전체 일일 30회에 도달하면 중지합니다. 30명보다 많아지면 늦게 등록한 사용자는 매일 생성 대상에서 밀릴 수 있어, 운영 시 이용자 수와 배분 방식을 다시 정해야 합니다. 사용자별 작업 상태를 DB에 남겨 중복 호출이나 수동 재호출이 같은 운세를 두 번 생성·과금하지 않도록 합니다. 장시간 실행 한도와 호출량 상한을 적용하고, 넘친 대상은 미처리로 남겨 운영자가 확인·재개할 수 있게 합니다.
- 오전 9시 이후 첫 등록의 생성 요청은 **인증된 해당 사용자**의 서버 작업에서 시작합니다. 등록 시점에 이미 같은 날짜 결과·시도 기록이 있는지 확인하고, Cron과 동일한 원자적 선점 절차로 한쪽만 Gemini 요청을 시작합니다. 등록 요청과 Cron이 겹치거나 사용자가 등록을 중복 제출해도 계정·한국 날짜당 최대 한 번만 시도합니다. `CRON_SECRET`과 Supabase secret key를 브라우저에 전달하지 않습니다.
- 첫 등록 후 즉시 생성도 **전체 계정 합계 일일 30회 상한**을 함께 적용합니다. 상한이 소진됐으면 Gemini를 호출하지 않고 `오늘의 운세 생성 한도에 도달했습니다`라는 상태를 보여줍니다. 등록 자체는 보존하며 운세가 준비됐다고 표시하지 않습니다. 등록 응답은 DB 저장 뒤 먼저 보내고, Gemini 생성은 응답 이후 서버 작업으로 실행합니다. 화면은 저장된 처리 상태를 다시 조회하며 생성이 오래 걸리거나 실패해도 요청을 무작정 다시 시작하지 않습니다. 저장 응답이 비거나 끊어지면 원시 JSON 오류를 보여주지 않고 프로필을 다시 조회하여 저장 성공 여부를 확인합니다.
- Vercel은 실패한 Cron을 자동으로 재시도하지 않습니다. 실패한 사용자만 식별 가능한 운영 상태(개인 내용 없는 코드·건수)를 남깁니다. 권한이 있는 운영자가 같은 날짜를 다시 실행하더라도 **아직 Gemini 요청을 시작하지 않은 작업만** 처리합니다. 이미 요청한 계정은 그날 다시 호출하지 않고 `오늘의 운세를 만들지 못했습니다`를 보여줍니다. AI 오류를 가짜 운세로 바꾸지 않습니다.
- 한국 날짜는 서버에서 `Asia/Seoul` 기준으로 계산합니다. 자정 경계 전후에 UTC 날짜를 오늘 날짜로 잘못 사용하는지 시험합니다.

## 데이터베이스와 권한 설계

- `public.saju_daily_profiles`: `user_id uuid`(사용자별 한 행·`auth.users` 연결), `birth_date date`, `birth_time time without time zone`(한국 현지 시각), `gender`(허용값 검사), `calendar_type='solar'`, 계산 기준 버전, 선택한 계정 저장 결과 `source_reading_id`(직접 입력이면 비움), 프로필 버전·등록·수정 시각을 저장합니다. 이 테이블이 **생년월일시·성별의 계정 저장 위치**이며, 기존 `saju_readings` 결과 행에는 원본 정보를 추가하지 않습니다. `source_reading_id`는 같은 사용자 소유만 연결하고, 저장 결과를 삭제하면 출처 연결만 비워 독립적인 `내 사주` 프로필을 보존합니다. 원본을 DB에 저장하므로 사용자가 확인·수정·삭제할 수 있어야 합니다.
- `public.saju_daily_fortunes`: `user_id`, `fortune_date date`(한국 날짜), 생성 당시 프로필 식별값·버전, 처리 상태, `gemini_attempted_at`, 검증된 결과 `jsonb`, 생성·실패 시각과 최소한의 오류 코드를 저장합니다. `(user_id, fortune_date)` 유일 제약으로 하루 한 건을 보장하고, 사용자·날짜 조회 인덱스를 둡니다. 동시 호출 시 원자적인 상태 선점으로 Gemini 중복 호출을 막습니다. 프로필 식별값은 삭제 후 같은 날 재등록하거나 동시 수정해도 이전 결과가 새 정보에 붙지 않게 합니다.
- 지난 운세 **본문은 다음 날 오전 9시 예약 실행 때 비웁니다.** 과거 운세 목록은 없으며 오늘 날짜의 결과만 조회합니다. 호출 횟수·시도 시각·실패 코드 같은 최소 운영 기록은 30일 후 자동 삭제합니다. 계정 또는 `내 사주` 삭제 시 운세 본문은 즉시 비웁니다.
- 프로필·운세·일일 호출량 테이블 모두에 RLS(행 단위 접근 제한)를 켭니다. 로그인 사용자는 자신의 프로필·오늘 운세만 조회할 수 있고, 호출량 테이블과 다른 계정의 행에는 접근할 수 없습니다. 비로그인 사용자는 접근할 수 없습니다. 프로필 등록·변경은 본인 인증과 입력 검증, 기존 결과 선택 시 소유권·8글자 일치를 서버에서 확인합니다. 프로필 수정·삭제도 본인에게만 허용하고, 운세 생성·상태 변경은 보호된 서버 작업만 할 수 있습니다. 실제 서로 다른 두 계정과 비로그인 상태의 허용·차단 검사를 완료해야 합니다.
- 출생 정보는 개인과 연결되는 민감한 자료로 취급합니다. 등록 화면에서 매일 운세 생성에 쓰려고 계정 DB에 보관한다는 사실을 알려주고, 로그·오류 응답·분석 도구·브라우저 `localStorage`·Gemini 요청에 원본을 복사하지 않습니다. 프로필 삭제 시 해당 원본 값이 더는 조회되지 않도록 합니다.
- 여러 사용자의 프로필을 읽고 쓰는 Cron의 Supabase **secret key**는 서버 전용으로 분리합니다. 브라우저용 publishable key나 로그인 쿠키와 혼용하지 않으며, secret key는 코드·Git·로그에 남기지 않습니다. Secret key는 RLS를 우회하므로 조회 대상과 쓰기 대상의 사용자 ID를 서버가 엄격히 확인합니다.
- 계정 삭제 시 프로필·운세도 함께 정리되는 외래 키와 삭제 정책을 설계합니다. 이번 화면은 과거 운세 목록을 제공하지 않습니다.

## 구현 순서와 완료 조건

1. 오늘의 운세용 Gemini 호출 상한을 **전체 계정 합계 하루 30회**로 설정하고 예상 등록자 수·Vercel 플랜을 확인합니다. 기존 계정 결과의 실제 두 계정 접근 차단 시험을 마칩니다.

3. 서버의 계산·Gemini 응답 검사·중복 방지·Cron 인증을 구현합니다. 비밀값 누락, 중복 실행, 부분 실패, 타임존 경계를 자동 검사합니다.

6. `npm run check`, `npm run build`, 실제 두 계정의 본인 결과 접근 제한, 보호된 Cron 시험 호출, 배포 사이트의 예약 실행 기록과 다음 날 09시대 실제 생성을 확인해야 완료입니다. 실제 Gemini 호출은 비용을 발생시키므로 예산 승인 후 소량의 시험 계정으로만 검증합니다.
