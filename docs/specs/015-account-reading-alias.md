# 015-account-reading-alias: 계정 저장 결과의 별칭

상태: 로컬 구현·자동 검사·운영 DB 구조 적용 완료 · 실제 계정 화면 검증·앱 배포 전

작성일: 2026-09-29

## 목표

- `사주 보기`에서 현재 해석 결과를 계정에 저장할 때 선택적으로 별칭을 입력합니다. 예: `내 사주`, `친구 사주`.
- 실명 입력은 요구하지 않고 별칭은 사주 계산·Gemini 요청·매일 운세 생성에 사용하지 않습니다.
- 사주 보기의 계정 저장 목록에는 별칭을 우선 표시합니다. 별칭이 없는 기존 결과는 일주(태어난 날의 두 글자)와 날짜로 표시합니다.

## 저장과 수정

- `public.saju_readings.alias`를 비워 둘 수 있는 `text` 칸으로 추가합니다. 기존 결과는 `null`로 유지하고 임의 별칭을 만들지 않습니다.
- 양끝 공백을 제거하며 1~30글자만 저장합니다. 줄바꿈·제어 문자는 허용하지 않습니다. 목록 안에서 같은 별칭을 여러 번 써도 됩니다.
- 저장한 결과를 다시 열어 별칭을 바꾸거나 비우고 `계정 저장 결과 업데이트`를 누를 수 있습니다. 새 주제 해석이 자동 반영될 때는 기존 별칭을 보존합니다.
- 별칭은 사용자 본인의 계정 저장 결과와 함께 기존 행 단위 접근 제한(RLS)을 따릅니다. 브라우저 저장 결과·출생 원본·오늘 운세 프로필에는 별칭을 복사하지 않습니다.
- 기존 배포 앱은 별칭 칸을 조회하지 않으므로 DB에 이 칸을 먼저 추가해도 기존 동작을 유지해야 합니다. 새 앱 배포는 마이그레이션 확인 후 진행합니다.

## 범위 밖

- 주소 경로 변경과 브라우저 뒤로가기 개선은 경로 이름 논의 후 별도 작업으로 합니다.
- 오늘의 운세 `저장된 사주 결과에서 가져오기` 선택지는 사용자 결정으로 제거합니다. 별칭은 결과 구별에만 도움을 주며 원본 출생정보를 복원하지는 못합니다.

## 완료 조건

1. 별칭 없이 저장한 기존 결과와 새 결과를 다시 열 수 있습니다.
2. 별칭 입력·변경·삭제가 계정 결과 한 건에 적용되고 목록에 반영됩니다.
3. 자동 주제 갱신이 별칭을 지우지 않습니다.
4. DB 제약·접근 제한, 자동 검사·빌드, 실제 계정 저장·조회 화면을 확인합니다.

## 검증 기록

- 운영 Supabase 프로젝트의 `public.saju_readings`에 nullable `alias text`와 길이·공백·제어문자 제약을 적용했습니다. 마이그레이션 버전은 `20260929051636`이며 로컬 파일과 맞췄습니다. 적용 전후에 기존 결과 테이블의 RLS 활성화와 결과 행 수 1건을 구조 조회로 확인했으며, 원본 해석·개인정보는 읽거나 변경하지 않았습니다.
- 독립 담당자가 별칭 파싱·정리·저장·수정·비우기·자동 갱신·응답 유실·마이그레이션 제약 테스트를 보강했습니다. 전체 `npm run check` 111건과 `npm run build`가 통과했습니다.
- 실제 계정 화면 검증은 아직 하지 않았습니다.
