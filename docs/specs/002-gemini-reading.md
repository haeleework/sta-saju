# 002-gemini-reading: Gemini 사주 해석과 브라우저 결과 저장

> 초기 구현 당시의 저장 방식을 기록합니다. 2026-09-29부터 브라우저 결과 저장·재열람은 중단했고, 현재 정책은 `016-account-only-reading-storage.md`를 따릅니다.

상태: 구현 및 기본 검증 완료 (2026-09-23)

작성일: 2026-09-23

## 목표

사용자가 기존 계산 결과를 확인한 뒤 쉬운 기본 해석과 선택한 관심 주제의 상세 해석을 읽고, 성공한 결과를 같은 브라우저에서 다시 열 수 있게 합니다. 로그인은 이 기능에 포함하지 않습니다.

## 사용자 흐름

1. 기존 화면에서 양력 생년월일과 출생시간을 입력해 사주를 계산합니다. 현재 계산기가 지원하지 않는 입력은 기존 오류 안내를 유지합니다.
2. 계산 결과 옆에 `해석 만들기` 동작과 안내를 표시합니다. 누르면 계산된 사주 구성이 Google Gemini 서비스로 전달된다는 점을 알립니다. 사용자가 누르기 전에는 Gemini를 호출하지 않습니다.
3. 기본 해석이 성공하면 쉬운 요약과 핵심 설명을 보여줍니다. 기존의 년·월·일·시주와 계산 기준도 함께 남깁니다.
4. 사용자가 `성격·강점`, `연애·관계`, `일·진로`, `재물` 중 하나를 선택하면 그 주제의 상세 해석을 요청합니다. 주제를 바꾸면 해당 주제의 결과를 보여줍니다.
5. 성공한 기본·주제별 결과는 브라우저에 저장합니다. 새로고침 후에도 저장 목록에서 다시 열 수 있으며, 사용자는 저장 결과를 삭제할 수 있습니다.

## 입력과 계산의 책임

- 사주 계산은 기존 `lib/saju`가 담당합니다. Gemini에게 생년월일로 사주를 다시 계산하라고 요청하지 않습니다.
- 서버는 날짜·시간을 다시 검증하고 사주 구성을 계산합니다. 브라우저에서 보낸 기둥·오행 수치를 그대로 신뢰하지 않습니다.
- Gemini에는 해석에 필요한 계산 결과와 선택한 주제만 전달합니다. 이름, 이메일, 원본 생년월일·출생시간, 브라우저 저장 목록은 전달하지 않습니다.
- 계산 기준(`양력`, 한국 표준시, 23시 일자 변경, 진태양시 보정 없음)을 해석에 반영하고, 계산 결과와 다른 기둥이나 오행을 새로 만들어내지 않도록 요청합니다.

## Gemini 호출과 결과 형식

- 모델 ID는 **`gemini-3.5-flash-lite`**로 고정합니다. 모델이 실패해도 별도의 모델로 조용히 바꾸지 않습니다.
- Google AI Studio에서 발급한 API 키는 서버 전용 `GEMINI_API_KEY` 설정값으로만 읽습니다. 브라우저 코드, 응답, `localStorage`, Git 파일에 키를 넣지 않습니다.
- 해석 요청은 서버에서만 수행합니다. 호출할 때 응답 형식을 JSON으로 지정하고, 서버에서 필수 필드·자료형·길이·빈 내용 여부를 다시 검사한 뒤 화면에 보냅니다.
- 기본 해석 필드: `summary`(쉬운 말로 된 요약), `highlights`(핵심 설명 2~3개), `caution`(해석의 한계). 주제별 해석 필드: `topic`, `title`, `reading`, `reflectionQuestion`(스스로 생각해 볼 질문).
- 해석은 가능한 성향과 관점을 설명하는 표현으로 씁니다. 미래를 확정하거나 질병·투자·법률 판단을 지시하는 문장은 허용하지 않습니다. `재물` 주제도 금융 조언처럼 표현하지 않습니다.
- 생성한 문장은 계산 사실과 구별해 `AI 해석`으로 표시합니다. 문장 길이와 어조의 세부 기준은 첫 실제 결과를 보고 검토합니다.

## 브라우저 저장 규칙

- 성공한 결과만 `localStorage`의 버전 있는 키(예: `saju-readings-v1`)에 저장합니다. 한 번의 계산은 한 결과 항목이며, 주제별 해석은 그 항목에 추가합니다.
- 항목에는 식별자, 생성 시각, 계산된 사주 구성, 기본 해석, 성공한 주제별 해석을 저장합니다. 원본 생년월일·출생시간과 API 키는 저장하지 않습니다.
- 같은 브라우저·같은 사이트에서 저장 결과를 다시 열 수 있습니다. 다른 기기나 브라우저로 자동 동기화되지 않으며, 브라우저 데이터를 지우면 결과도 사라질 수 있음을 화면에 알립니다.
- 저장 목록에서 개별 항목 삭제를 제공하며, 지우기 전에 대상을 분명히 보여줍니다. 저장 공간 부족 또는 차단으로 저장에 실패하면 해석은 화면에 남기되 `저장되지 않았습니다`라고 알려줍니다.
- 저장된 자료의 형식이 맞지 않거나 예전 버전이면 오류로 화면이 멈추지 않게 하고, 해당 항목을 임의로 덮어쓰지 않습니다.

## 실패와 재시도

- 입력 오류: 기존 계산 오류를 보여주고 Gemini를 호출하지 않습니다.
- 키 누락·권한 오류: 설정 문제를 알리며 해석 성공 화면과 저장을 만들지 않습니다. 키 값 자체는 노출하지 않습니다.
- 호출 지연·횟수 제한·서버 오류: 실패 사실과 재시도 버튼을 보여줍니다. 같은 요청이 중복 제출되지 않도록 생성 중 버튼을 비활성화합니다.
- 빈 응답·형식 불일치·계산 결과와 명시적으로 다른 년·월·일·시주 또는 오행 개수: 결과를 실패로 처리합니다. 그럴듯한 가짜 해석으로 대체하거나 저장하지 않습니다. 문장의 모든 의미상 모순을 자동으로 판정할 수는 없어 생성 문구의 실제 품질은 사람이 계속 확인해야 합니다.
- 주제별 해석 실패: 이미 성공한 기본 해석은 유지하고, 실패한 주제만 다시 요청할 수 있게 합니다.

## 이번 범위에서 제외

구글 로그인, 서버 계정별 저장, 여러 기기 동기화, 자유 질문, 결제, 결과 공유. 기존 `001-prototype-flow.md`의 계산·주제 선택 흐름은 유지합니다.

## 완료 조건과 검사

1. 정상 입력으로 기본 해석을 생성하면 계산 결과와 구별된 AI 해석이 보입니다. 주제 하나를 고르면 해당 주제의 해석이 별도로 보입니다.
2. 응답 형식이 잘못되거나 키가 없거나 호출이 실패하면 오류가 보이고 실패한 결과는 저장되지 않습니다. 재시도로 성공하면 정상 표시됩니다.
3. 저장한 결과는 새로고침 후 다시 열리며, 삭제한 항목은 목록에서 사라집니다. 저장에 실패한 경우에는 사용자에게 그 사실이 보입니다.
4. API 키는 브라우저로 전달되지 않고, 원본 생년월일·출생시간은 `localStorage`와 Gemini 요청에 포함되지 않습니다.
5. 기존 사주 계산 테스트, 서버 응답 형식·오류 처리 테스트, 실제 화면에서 성공·실패·재시도 흐름을 모두 확인한 뒤에만 완료로 표시합니다.

## 운영 전에 확인할 사항

- 로컬 `.env`에 설정된 API 키로 기능 검증을 했습니다. 키 값은 문서·대화·Git에 기록하지 않았으며, 다른 환경에서 실행할 때는 해당 환경의 `GEMINI_API_KEY`를 별도로 설정해야 합니다.
- 공개 배포 전에는 API 호출 남용과 비용을 막을 제한 방식을 결정합니다.
- 해석 문장 길이·어조는 실제 생성 예시를 보고 참가자와 최종 확인합니다.
