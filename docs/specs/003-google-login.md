# 003-google-login: 구글 계정 로그인

상태: 정책 변경 반영 · 실제 로그인 확인 전

작성일: 2026-09-23

## 목표와 결정

- 2026-09-23에 사용자가 정책을 변경했습니다. 로그인 전 사주 서비스 전체를 막으며, 구체적인 접근 제한은 `006-login-required-service.md`를 따릅니다.
- 과거 `localStorage` 목록은 계정으로 자동 이전하지 않습니다.
- 이미 로그인한 사용자는 같은 버튼에서 로그인 단계를 건너뛰고 현재 결과 저장으로 이동합니다. 실제 저장 규칙은 `004-account-reading-storage.md`를 따릅니다.
- 이번에 Codex에 연결한 Supabase MCP의 개발자 인증과 서비스 방문자의 구글 로그인은 **서로 다른 인증**입니다. 앱의 구글 로그인은 별도 Supabase Auth 설정이 필요합니다.

## 사용자 흐름

1. 방문자는 구글 로그인 전에는 사주 입력·계산·해석·브라우저 저장 목록을 사용할 수 없습니다.
2. 로그인 후 현재 사주 흐름을 이용하고, 추후 `계정에 저장`을 누르면 **현재 결과 한 건만** 계정에 저장합니다.
3. 사용자가 구글 계정을 선택·승인하면 앱으로 돌아옵니다. 앱은 로그인 성공 여부를 확인한 뒤 사주 화면을 엽니다. 계정 저장은 이후 별도 명시적 동작입니다.
4. 저장 성공 여부는 로그인 성공 여부와 별도로 표시합니다. 로그인만 성공하고 저장이 실패했다면 `저장되지 않았습니다`와 재시도 동작을 보여줍니다.
5. 로그인한 사용자는 자신의 계정 저장 목록을 열 수 있고 로그아웃할 수 있습니다. 로그아웃하면 계정 저장 목록을 화면에서 지우며 서버에서 다시 가져오지 않습니다. 브라우저에 원래 저장된 방문자 결과는 별개라는 점을 안내합니다.
6. 로그아웃 후 `Google로 로그인`을 다시 누르면 구글 계정 선택을 요청합니다. 서비스 로그아웃은 구글 자체의 로그인 상태를 종료하지 않으므로, 이 요청이 없으면 이전 계정으로 바로 로그인될 수 있습니다. 세부 동작과 검증은 `013-google-account-selection.md`를 따릅니다.

## Supabase Auth 구성

- 현재 Next.js 16 App Router에 Supabase Auth의 Google 제공자를 사용합니다. Google Cloud에서 웹 OAuth 클라이언트를 만들고, Supabase 프로젝트의 Google 제공자에 클라이언트 ID·비밀값을 설정합니다. Google 승인 화면에는 로그인에 필요한 기본 범위(`openid`, 이메일, 프로필)만 요청하고 Google Drive 등 추가 접근은 요청하지 않습니다.
- Google의 승인된 출처에는 실제 앱 주소를, 승인된 리디렉션 URI에는 **Supabase 대시보드가 표시하는 콜백 주소**를 등록합니다. Supabase의 허용된 리디렉션 주소에는 앱의 `/auth/callback` 경로를 로컬과 배포 환경별로 등록합니다. 주소를 추측해 입력하지 않습니다.
- Next.js에서 브라우저·서버용 Supabase 클라이언트를 구분하고 `@supabase/ssr`의 쿠키 기반 세션을 사용합니다. Next.js 16의 `proxy.ts`로 만료된 인증 정보를 갱신합니다. `/auth/callback`은 인증 코드를 세션으로 교환한 뒤 허용된 앱 내부 경로로만 돌려보냅니다. 외부 주소로 임의 이동시키는 `next` 값은 허용하지 않습니다.
- 프로젝트 URL과 공개 가능한 publishable key는 앱 설정으로 분리합니다. Google 클라이언트 비밀값, Supabase secret/service-role key, 사용자 세션 토큰을 소스 코드·Git·로그에 넣지 않습니다. 공개 키는 비밀키가 아니지만 데이터 접근은 반드시 `004`의 데이터베이스 권한과 행 단위 접근 제한으로 보호합니다.
- 서버에서 사용자 본인 확인이 필요한 경우 검증된 인증 정보(`getClaims` 또는 신선한 사용자 조회)를 사용하고, 브라우저가 보낸 `user_id`나 검증되지 않은 세션 객체만 믿지 않습니다.

## 오류·경계 상황

- 구글 승인 취소, 로그인 실패, 허용되지 않은 복귀 주소: 사주 화면을 열지 않고 재시도 방법을 보여줍니다.
- 로그인 중 탭 종료·새로고침: 인증을 다시 확인하기 전에는 사주 화면을 열지 않습니다.
- 계정 선택 화면에서 취소하면 로그인 전 화면에 남고 재시도할 수 있어야 합니다.
- 세션 만료: 계정 목록이나 저장 시 재로그인을 요청합니다. 다른 사람의 결과를 임시로 보여주지 않습니다.
- 로그아웃·다른 구글 계정 로그인: 이전 계정의 클라우드 결과와 메모리 캐시를 즉시 비우고 새 계정의 결과만 불러옵니다. 브라우저에 원래 남아 있는 방문자 결과가 다른 사람에게 보일 수 있으므로 공용 기기 주의 문구를 제공합니다.
- 인증 중에는 버튼을 비활성화해 중복 시작을 막습니다. 인증 코드, 접근 토큰, 비밀값을 URL 내 임의 경로·오류 문구·분석 로그에 노출하지 않습니다.

## 이번 범위에서 제외

이메일·비밀번호 로그인, 다른 소셜 로그인, 계정 병합, 기존 브라우저 저장 목록 일괄 이전, 결제, 결과 공유. 계정 삭제와 데이터 보존 기간은 공개 운영 전에 별도로 결정합니다.

## 완료 조건과 검사

1. 로그인하지 않은 상태에서는 사주 화면이 보이지 않고 해석 API가 인증되지 않은 요청을 거절합니다.
2. 로그인 성공 후 현재 결과 한 건의 저장이 이어지고, 과거 브라우저 결과는 업로드되지 않습니다. 로그인 성공과 저장 성공은 각각 확인됩니다.
3. 승인 취소·오류·세션 만료 후에는 사주 화면에 접근할 수 없고, 성공하지 않은 저장을 완료로 표시하지 않습니다.
4. 로그아웃·다른 계정 전환 후 이전 계정의 클라우드 결과가 보이지 않습니다.
5. 로컬 주소와 배포 주소 각각에서 콜백을 검증하고, 잘못된 복귀 주소와 토큰 누출을 검사합니다. 기존 해석 자동 검사와 실제 화면 흐름도 다시 확인합니다.

## 구현 전 확인

- 이번에 MCP로 연결한 Supabase 프로젝트를 앱의 Auth·데이터베이스 대상으로 사용한다는 가정입니다. 구현 전에 대상 프로젝트를 다시 확인합니다.
- Google Cloud OAuth 클라이언트와 Supabase Google 제공자 설정은 아직 검증하지 않았습니다. 사용자 계정으로 로그인하거나 승인하는 단계는 참가자가 직접 진행합니다.
- 공개 배포 주소가 정해지면 해당 주소의 출처와 콜백 허용 목록을 추가합니다.

## 검증 결과

구글 로그인·콜백 코드와 `006`의 로그인 필수화 코드는 작성했습니다. 자동 검사와 빌드는 통과했지만 실제 구글 계정 흐름 및 계정 저장은 아직 검증하거나 구현하지 않았습니다.
